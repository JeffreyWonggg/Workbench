# 工作台 Workbench

完全离线运行的个人工作台。待办、周报、笔记、记账、菜谱、记谱（和弦谱）、资料库、项目、收藏、代码（git）、更新软件版本、局域网传文件都在同一套界面里，**数据保存在你自己的文件夹中，不上传任何服务器**。

---

## 一分钟上手

1. 双击 **`打开工作台.bat`** —— 启动本地服务并打开 `http://127.0.0.1:47321/`
2. 首次使用会要求**选择一个数据文件夹**（待办/周报/笔记等会写进去，建议专门建一个空文件夹，比如 `D:\WorkbenchData`）
3. 需要局域网传文件时，先双击一次 **`启用局域网访问.bat`**（见下文「局域网」）

> 建议始终用 `打开工作台.bat` 进入，即 `http://127.0.0.1` 这个地址。用 `file://` 直接双击 HTML 打开会缺少本地服务能力。

## 功能一览

| 页面 | 做什么 |
|---|---|
| **工作台**（首页） | 今天到期的待办、本周概览、可配置的工具启动菜单、DeepSeek 充值余额、出行路况（一条固定线路的驾车耗时/路况 + 时段统计） |
| **项目** | 按项目聚合待办/笔记/周报工时/资料/代码/软件号；总览页显示每个项目的概况，点「布局」可拖动磁贴调整项目先后顺序（写进 `meta.json`，会跟着云同步走） |
| **待办** | 待办与状态、截止日、项目归属；填「持续天数」自动算截止日（当天算第 1 天）；逾期会在侧栏角标提醒 |
| **周报** | 按周记录各项目的工时与工作项；可从「已完成待办」一键填入；支持 AI 润色/扩写并导出 Markdown |
| **笔记** | 分级标题的块式笔记，支持表格、块内编辑、上下移动、项目归属；可导入 `.md` 文件（文件名作标题，导入时选归属项目） |
| **资料库** | 账号密码、路径、主机等条目；**主密码加密存储**（PBKDF2-SHA256 + AES-GCM），可记住密码、导出明文、从备份回滚 |
| **记账** | 记支出/收入（金额只填正数，收支由类型区分）、日期、分类（可自定义）与备注；也可以**口述记账**——在页头输入「昨天打车 38」，模型把它解析成字段填进弹窗，核对后保存；本月支出/收入/结余统计（含日均、比上月）、关键词搜索、按类型筛选、上下月翻看；明文 `ledger.json`，已纳入云同步 |
| **菜谱** | 记录菜名、分类、食材清单、做法步骤；支持关键词搜索与分类筛选、展开收起全文；删除进回收站可恢复；`Ctrl+K` 可搜 |
| **记谱** | 吉他弹唱和弦谱：谱面就是一段纯文本（和弦一行、歌词一行、空格对齐），支持段落标题、擅长和弦、转调、点和弦试听（详见「记谱」一章） |
| **快捷方式** | 常用文件 / 文件夹 / 网址做成卡片，点一下用系统默认程序打开；可增删改，清单存在 `meta.json` 的 `shortcuts` 字段里 |
| **剪贴板** | 查看本地服务记录的剪贴板历史（`Alt+Q` / `Alt+E` 那套）：搜索、展开长文本、一键复制回剪贴板、一键清空全部（需确认，不进回收站）；列表分页，每页 20 条，本机最多留最近 200 条；只在本机 `127.0.0.1` 显示 |
| **收藏** | 把文件或整个文件夹拖进来就存进数据文件夹（本体进 `files/`，截图进 `screenshot/`）；卡片带缩略图预览、搜索、按「文件/截图」筛选、可另存回本机 |
| **代码** | 本机 git 仓库管理：扫描发现、状态、改动暂存/提交（提交说明留空记为 `N/A`）、历史与差异、分支、标签、获取/拉取/推送（含强制推送）、反向提交与硬回滚、发布流水、软件号（明文） |
| **局域网传文件** | 手机/其它电脑在同一 WiFi 下打开局域网地址即可上传下载（支持整个文件夹、打包下载） |
| **产品目录查询** | 按序列号查产品数据所在的目录：页面里填几个根目录（存在 `workbench.config.json` 的 `catalogRoots`），服务端按 `根目录\spec\PN\SN` 三级扫描、索引常驻内存，查询毫秒级 |
| **更新软件版本** | 编辑 `UpdateVersion.ini`：改版本、复制条目、发布前预览、一键发布；与「代码」页的标签/发布流水联动 |
| **回收站** | 软删除的待办/笔记/菜谱在这里恢复或彻底删除（资料库的条目加密存放，只能在资料库页里恢复） |
| **关于** | 本页所有文字（名称、简介、作者、版本、版权）都读根目录的 **`about.json`**，改完刷新即可 |

**通用**：深色/浅色主题、侧栏可拖动排序、侧栏底部「设置」可关掉不用的页面、`Ctrl+K` 命令面板（可搜页面/待办/笔记/资料/软件号/菜谱）、全局撤销（删除后 Toast 带「撤销」）、危险操作一律用页面内的确认弹窗（不用浏览器原生弹窗）。

**云同步（可选）**：待办/周报/笔记/记账/菜谱/软件号/资料库/记谱加密后同步到腾讯云 CloudBase，手机浏览器打开 HTTPS 页面就能接着用；两台设备改同一处会保留冲突副本。请求也做得很省——不做后台轮询，切页/刷新不会白读云端；读回来的也不会是浏览器缓存里的旧副本（详见「云同步」一章）。

## 记谱（和弦谱）

和弦谱页的设计原则是**纯文本即唯一真源**：一首歌的谱面就是一整段文本，和弦占一行、歌词占一行，靠列对齐对上位置。转调、复制、打印、手工修改都只动字符，不依赖任何结构化格式——从网上复制来的谱子不用转换就能用。

### 输入方式

1. **两行式**（唯一的写法）：和弦行写在歌词行上方，用空格对齐——和弦打在哪个字上面，就落在哪一列。从网上复制来的谱子直接就是这个形式，不用转换。
2. **段落标题**：单独占一行，写 `[主歌]`，或者直接写 `副歌`、`间奏` 这类词；方括号里放**段落名**，不要用来包和弦。
3. **和弦面板 + 前缀补全**：面板里列的是当前调内的常用和弦（含你自己标进「擅长和弦」的），点一下插到光标处；在谱面里敲 `Am` 的前几个字符会弹候选，按 `Tab` 采纳。

### 其它

- **转调**：列表卡片上的「转调」选目标调（弹窗里同时列出推荐调），「应用」覆盖原曲、「应用并另存」留一份新歌
- **试听**：点预览或查看页里的和弦会发声（WebAudio 合成，无外部依赖、不走网络），音量在编辑器工具栏右侧
- **删除**：不做回收站，删掉后在 Toast 里可以「撤销」一次，歌会回到原来的位置

数据文件：`charts.json`（歌曲）+ `chart-settings.json`（擅长和弦、推荐调权重、音量）。**歌曲、擅长和弦、推荐调权重都纳入云同步**，手机上能接着电脑上的谱子继续用；只有音量留在各台设备——手机和电脑该各留各的（详见「云同步 → 同步哪些数据」）。

## 界面与设置

侧栏底部（数据文件夹和「项目」入口的下方）依次是**深色模式**和**设置**两个按钮，再下面是「Ctrl+K 搜索」提示。

### 设置：关掉不用的页面

「设置」里列出全部页面，勾选框控制它**是否出现在侧栏和 `Ctrl+K` 搜索里**。关掉一个页面意味着：

- 侧栏和 `Ctrl+K` 里都不再出现（两处始终一致）
- 其它页面上指向它的链接（比如项目页的「待办 / 笔记 / 代码」）**不会跳过去**，而是弹出提示说明该页面已被关掉，并给一个「打开设置」的入口，点了直接打开设置面板并把对应那一行高亮出来
- **页面本身没动**：直接输网址照样能打开，功能完全照旧，随时能勾回来
- **位置保留**：拖动排序存的是完整顺序（含关掉的页面），所以关掉再打开会回到原来的槽位，不会跑到末尾
- 全部关掉时侧栏会提示一句「侧栏是空的。点下面「设置」把页面打开。」；设置入口不受自身开关影响，不会把自己锁在外面

> 说明：关掉侧栏项**不省资源**。每个页面只有在你打开时才加载自己的 JS 和数据，侧栏那几行字不加载任何东西。真要省资源，该关的是「进入某页时的自动行为」（例如代码页一进去就递归扫描仓库）。

### 危险操作统一确认

删除、重置、导出、迁出这类操作用的是页面内的毛玻璃弹窗，**全库没有浏览器原生 `confirm()` / `alert()` / `prompt()`**（原生弹窗由系统绘制，和整套界面不是一个观感）。目前统一走 `Nav.ask()` 的有 13 处：回收站（彻底删除待办/笔记/菜谱、清空回收站）、资料库（重置、导出明文、彻底删除条目、批量迁出软件号）、快捷方式（删除卡片）、收藏（删除文件）、记账（删除记录）、更新软件版本（有未保存修改时发布）、局域网传文件（删除文件/文件夹）；云同步面板的确认与冲突查看也复用同一套。周报、菜谱、记谱用的是各页自己的同款对话框（`<dialog>` + 同一套样式）。

行为与原生一致：**确定 → 执行；取消 / Esc / 点弹窗外的遮罩 → 放弃**。危险操作用红色按钮，并且**默认焦点落在「取消」**上，避免一路回车把东西删了；删除类操作大多还能在 Toast 里点「撤销」恢复。

### 本机偏好存在哪里

| 偏好 | `localStorage` 键 |
|---|---|
| 主题（深色/浅色） | `wb-theme` |
| 侧栏顺序 | `wb-nav-order` |
| 关掉的页面 | `wb-hidden-pages` |

这些**跟着浏览器走，不跟着数据文件夹走**：换电脑、换浏览器或清了站点数据，需要重新设一次（数据本身当然还在你的数据文件夹里）。

## 技术框架

**设计取向：零依赖、零构建、离线优先。** 没有 npm、没有 bundler、没有 CDN 请求，克隆下来就能跑。

| 层 | 用的东西 |
|---|---|
| 前端 | 原生 HTML + CSS + ES2020 JavaScript（无框架），模块以 IIFE 挂到 `window`（`Workbench` / `Nav` / `GitApi` / `Storage` / `VaultCrypto` 等） |
| 样式 | 单文件 `css/app.css`，CSS 变量 + `[data-theme]` 双主题；字体本地自托管（`fonts/*.woff2`） |
| 数据读写 | **File System Access API**：用户自己选数据文件夹，句柄存 IndexedDB，数据以纯 JSON 文件落地（`meta.json`、`todos.json`、`notes.json`、`reports.json`、`notes/`、`software.json`、`commute.json`…） |
| 加密 | WebCrypto：PBKDF2-SHA256 派生密钥 + AES-GCM 加密资料库（`vault.json`），每次写入自动留 `vault.backup.json` |
| 本地服务 | **C# / .NET Framework**（`scripts/workbench-host.cs`，用 `csc` 编译成单个 `workbench-host.exe`），`HttpListener` 提供 HTTP 接口，WinForms 弹原生文件/文件夹选择框 |
| 产品目录索引 | 由本地服务扫盘建立：按 `根目录\spec\PN\SN` 三级扫描，索引常驻服务端内存、快照存 `catalog-index.json`；浏览器不再读写任何 `.db` |
| 二维码 | 自带 `js/vendor/qrcode.js` |
| AI | 兼容 OpenAI 协议的 `chat/completions` 接口（DeepSeek / 火山方舟），密钥放本机 `js/openrouter.local.js`；首页余额卡片另查官方 `GET /user/balance` |

### 本地服务接口

| 接口 | 用途 |
|---|---|
| `GET /` 及静态文件 | 提供页面；有屏蔽名单，禁止路径穿越 |
| `POST /open` | 用系统默认程序打开本机文件/文件夹 |
| `POST /run-tool` | 按 `meta.json` 的 `tools` 配置启动本机程序 |
| `POST /publish`、`GET/POST /update-version-ini` | 更新软件版本的预览与发布 |
| `GET/POST /config` | 读写本机配置（如 `UpdateVersion.ini` 路径） |
| `POST /pick-file` | 弹 Windows 原生对话框（`mode=file` 选文件 / `mode=dir` 选文件夹） |
| `GET /fs/list` | 列目录（页面内目录浏览器用） |
| `/lan/*` | 局域网传文件的列表、上传、下载、删除、打包 zip |
| `/git/*` | `scan` / `status` / `log` / `diff` / `branches` / `tags` / `exec` |
| `/baidu/*` | 出行路况：`route` 取路况（顺带带回分段明细）、`suggest` 地点候选、`geocode` 地址解析、`status` AK 是否已配、`watch` 同步线路给后端、`spool` 存取后端趁页面没开时采的样本 |

**安全约束**（重要）：所有写操作都校验来源（只认 `http://127.0.0.1:47321`），局域网来源一律 403；`/git/*` 更进一步——**客户端只说“做什么动作”，命令行由服务端白名单拼装**，从根上避免参数注入；仓库必须位于已登记的代码根目录下，路径不允许含 `..`。

## 局域网传文件

1. 双击一次 **`启用局域网访问.bat`**。它会检查两件事并以普通用户身份完成能做的部分：
   - `http://+:47321/` 的 **URL 保留**（缺了服务就只能监听 127.0.0.1，局域网连不上）
   - **防火墙**是否放行 TCP 47321（仅当防火墙处于开启状态才需要）
   - 缺配置时会打印出需要**管理员权限执行一次**的命令（可直接交给 IT），并照常把服务重启好 —— 本机使用不受影响
2. 打开「局域网传文件」页，复制显示的地址（或让对方扫二维码），对方用浏览器打开即可上传/下载
3. 支持直接拖入整个文件夹；隐藏文件/文件夹（`.git` 等）会被跳过，这是设计如此
4. 同名文件**不会覆盖**已有的：上传时自动另存为 `报告 (1).pdf`，列表里两份都在（避免手滑把别人刚传的文件顶掉）

> 公司电脑若没有管理员权限：URL 保留和防火墙规则都无法自行添加，需要 IT 授权一次。局域网地址走的是明文 HTTP，因此**数据页（待办/资料库等）在其它设备上不可用**，页面会明确提示，只有不需要数据文件夹的「局域网传文件」等页面可用。

## DeepSeek 余额（可选）

首页有一块「DeepSeek」，显示**充值余额**，底下一行是**总额**、**赠金**和更新时间，用的是周报 AI 同一个密钥。都来自官方接口 `GET https://api.deepseek.com/user/balance`：`topped_up_balance` 当充值余额、`total_balance` 当总额、`granted_balance` 当赠金，带 `Authorization: Bearer <你的 Key>`。实测该接口会回显 `access-control-allow-origin`，所以**浏览器直连就行，不经过本地服务，也不用重编译 exe**。

这里**不显示消费**。官方没有用量或账单接口（API 文档里只有 Chat / Responses / FIM / 模型列表 / 余额 / 文件，控制台那个数字不对外开放）。曾经拿余额快照做减法算「当天 / 当月消费」，但那个算法假设余额只减不增：一充值，被减数就比减数大，负数被 `Math.max(0, …)` 压成 **0**——当天要等花超充值额才重新有数，当月更是整月少算。算不准不如不算，所以删掉了；要看消费，点卡片上的「说明」，里面有**打开平台用量页**的链接。

几点说明：

- 5 分钟内不重复请求，点「刷新」可以强制。断网或接口失败时显示上次的数字，并在下面标一行原因
- `deepseek.json` 现在只作余额缓存（明文，可读可改），不再存按天快照；旧版本留下的 `days` 会在下次刷新写盘时自动丢掉
- 没配密钥、接口返回 401 或连不上时，卡片只显示原因和「重新读取」，不影响首页其它部分

## 出行路况（可选）

首页有一块「出行路况」，盯**一条固定驾车线路**（比如家 → 公司），每 15 分钟问一次百度地图，回答两件事：**现在走值不值**（耗时、里程、实时路况、相对近期均值快了还是慢了），以及**不同时间段的规律**（按工作日 / 周末分别聚合的 24 小时平均耗时条形图、最近 30 天热力格、最堵时段）。

### 申请百度 AK（三步）

1. 打开 [百度地图开放平台](https://lbsyun.baidu.com/) → 右上角控制台，注册并**完成个人认证**（未认证的额度很小）
2. 控制台 → **应用管理 → 创建应用**：应用类型选 **「服务端」**，接口勾上 **「地理编码」**、**「路线规划」** 和 **「地点检索」**。创建完就能看到 AK。少勾一个也不会整块不能用：「地点检索」缺了只是设置线路时没有候选可挑，「路线规划」缺了就是完全取不到路况——耗时、统计和分段明细全靠它
3. 把 AK 填进仓库根目录的 `baidu.local.json`（`{"ak": "你的AK"}`），然后重启工作台（双击 `打开工作台.bat`）

**一定要选「服务端」**，不要选浏览器端：浏览器端 AK 会限制 Referer，而这里的请求是从本机服务发出去的；服务端 AK 走 **IP 白名单**，留空表示不限制，要填就填本机出口 IP。

### 为什么绕本机服务走

百度地图的 Web 服务 API **多数不返回 CORS 头**，浏览器直接 fetch 会被拦。所以页面只打同源接口（`GET /baidu/route` 取路况、`GET /baidu/suggest` 取地点候选、`GET /baidu/geocode` 只解析地址），由 `workbench-host.exe` 拿着 `baidu.local.json` 里的 AK 去问百度，再把精简结果回给页面。这样三件事一起解决：

- 跨域没了（页面和本机服务同源）
- **AK 不进页面源码**：`baidu.local.json` 不进版本库，接口只回一个"是否已配置"的布尔值，密钥永远不出现在 HTML / JS 里
- 手机上经局域网地址打开也能用（这个接口是只读的，和 `局域网传文件` 一样不做本机校验）

改过 `scripts/workbench-host.cs` 的话，记得按「重新编译本地服务」那节重编译重启。

### 几个细节

- **起点终点从候选里选最稳**：设置里敲两个字，百度会给出候选（`/baidu/suggest`），选中就是它自己的规范地点和坐标，不用再猜。手输也行，只是保存前会先解析一遍、把结果显示在弹窗里；一旦百度**没能精确匹配**（`precise≠1`，例如「东莞厚街万达」少了「市」字被认成北京石景山万达广场），就先停下来问一次，确认过才存——免得存进一条错线路天天算。想跳过这一步就直接填 `纬度,经度`
- **地址会转成坐标再缓存**：百度路线规划只吃「纬度,经度」，所以第一次会先做一次地理编码，坐标存进 `commute.json`，之后直接发坐标——省配额，也避免同名地点漂移
- **15 分钟一次，页面关着也在采**：实时路况的更新粒度大概就是 5–15 分钟，再密只是重复读同一份数据，所以页面和服务端都按 15 分钟走。页面打开时由页面取（在后台不请求，省配额也省电）；**页面没开的那段时间由 `workbench-host.exe` 自己在后台取**——线路会在页面打开、改线路时同步给服务端（存进根目录 `commute.local.json`，里面有起终点，不进版本库），采到的样本先攒在根目录 `commute-spool.json`，页面下次打开时取回来、按时间戳并进数据文件夹的 `commute.json`。两边共用同一条采集时间线（页面自己采的那条也会回传一份），再加上「同一线路 60 秒内直接返回上次结果」，实际用量比「两边各采各的」更低。卡片上的「刷新」可以随时手动取一次
- **耗时口径跟百度地图 APP 对齐**：卡片上的耗时、里程、路况走**「路线规划」**（`direction/v2/driving` + `steps_info=1`）。以前走的是「驾车路线规划(轻量)」，实测同一条 117 公里线路它报 106 分钟、完整版报 90 分钟（距离都是 117.2 公里，差在时间估算），而 APP 用的是后者的口径——所以整块换成了完整版。代价是走「路线规划」的配额，返回体从 0.3 KB 变成约 48 KB（15 分钟一次，可以忽略）
- **分段明细顺手就带回来了**：同一个请求里已经有每一段的路名、里程、耗时，以及这段里畅通多少米、缓行多少米、堵了多少米（每段还带一串路径坐标，服务端丢掉不用）。点「看分段路况」通常直接命中 60 秒内的那次采集结果，不会再打一次百度；页面只列缓行以上的段，按严重程度排前 8 条。卡片上那行路况只放最堵的一档（如「拥堵 6.4 公里」），四档全报一行放不下
- **换接口之前攒的样本是旧口径**：那批耗时由轻量版产生，系统性偏高约 15%，和之后的新样本画在同一条曲线上会看到一个向下的台阶——不影响同一时间段内的横向比较，心里有数即可
- **更早的一批样本时间戳差 8 小时**：后端把「本机时间」转 Unix 毫秒时漏了时区换算，等于把北京时间当成 UTC，于是**它自己采的**样本时间戳多了 8 小时——周五晚上 23:48 采的会落到周六 07:48，看起来就像"周末早上冒出一条记录"（已修）。页面自己采的那批不受影响（`new Date(at)` 本来就是按本地时间解析的）。要是统计里出现某个时段根本没用过的记录，把数据文件夹 `commute.json` 里**时间戳落在未来**的那几条删掉就行
- **每次取到的数据都会留下来**：追加一条样本到数据文件夹的 `commute.json`（`t` 时间、`d` 耗时秒、`m` 距离米、`x` 路况文案），保留 180 天且最多 12000 条。样本是统计的唯一依据——**刚开始几天条形图会很稀**，攒够样本才看得出早晚高峰
- **结论怎么来的**：优先跟「当前小时段 + 当前是工作日/周末」的历史均值比，那个时段样本不足 3 条时退回最近 24 小时均值。条形图的纵轴按工作日/周末两组的共同最大值归一，所以切换两组时柱高可以直接比
- 没配 AK、地址解析不出来、配额超限、网络不通，都会在卡片上给一句能看懂的原因（不是干巴巴的错误码），并且保留上一次的数据

## 云同步（可选）

数据先在本地加密，再传到腾讯云 CloudBase 云存储。电脑端照旧用「数据文件夹」（明文 JSON，随时能自己打开改），手机端用浏览器打开 HTTPS 页面，数据落在 IndexedDB，**云端是权威副本**。

### 开一次要做的五件事

1. 腾讯云控制台开通 **CloudBase 云开发**，建一个环境，复制**环境 ID**（形如 `workbench-1a2b3c`）
2. 控制台 → 登录授权 → 打开**匿名登录**（同步用它换临时凭证，密钥不进前端）
3. 控制台 → **云存储** → 建一个桶，名字用 **`workbench`**（代码里默认就认这个桶名），并让匿名身份能读写它
4. 把这份页面放到任意 **HTTPS** 静态托管（CloudBase 静态网站托管自带 `https://xxx.tcloudbaseapp.com`，也可以用 Vercel / GitHub Pages），手机访问这个地址（发布与更新见「更新发布的页面」一章）
5. 工作台「设置 → 云同步」里填环境 ID、设一个同步密码（至少 6 位，别和资料库主密码一样），点「开启同步」，再选第一次以哪边为准

第 5 步不是只试着登录一下：它会**真往云端写一个探针文件再读回来**，确认「登录、桶、读写权限」三样都通才继续。哪一样不通就当场报错，并告诉你该去控制台改什么（候选里有旧域名 / 桶不存在 / 权限策略 / 环境 ID 之分）；失败会自动回滚这次配置，不会留半套。

手机上不想手输环境 ID：电脑端把第 4 步的地址填进「手机访问地址」，面板会生成一个二维码，用手机相机扫一下就会打开工作台并带上环境 ID，再输一次同步密码即可。

### 同步哪些数据

| 同步 | 不同步 |
|---|---|
| 待办 `todos.json`、周报 `reports.json`、笔记索引 `notes.json` + 每篇正文 `notes/*.md`、记账 `ledger.json`、菜谱 `recipes.json`、软件号 `software.json`、加密资料库 `vault.json`、记谱 `charts.json`、记谱偏好 `chart-settings.json`（只取擅长和弦与推荐调权重） | 剪贴板历史、OTDR 索引、局域网收到的文件、`workbench.config.json`、API Key |
| 项目清单：只取 `meta.json` 里的项目名，工具路径、git 根目录这些**本机路径不外传** | DeepSeek 余额缓存 `deepseek.json`（每台设备各查各的，同步过去只会互相覆盖、反复产生冲突副本）、出行记录 `commute.json`（里面有起点终点，还按 15 分钟一条攒着，各设备各采各的）、记谱的音量（擅长和弦与推荐调权重会同步，音量是设备属性，各台设备各留各的）、收藏 `files.json`（它指向 `files/` 里的二进制本体，那些不上云，同步过去只会得到一堆打不开的卡片）、资料库主密码、明文缓存 `wb-vault-records`、旧版明文资料库 `resources.json`（建议直接删掉） |

这张表不是死的：面板里「会同步哪些数据」区块会按这台设备**实际有什么**列出来，标上各自大小和待推送篇数，改动前后一眼能看出哪类还没上云。同一个区块也把「不上云」写在末尾，不用回来翻文档。

### 两台设备改了同一处怎么办

按文件或一篇笔记判定：谁后写谁说了算，被覆盖的那版自动存成**冲突副本**（笔记会多一条「（冲突副本 · 设备 · 时间）」，JSON 会多一个 `*.conflict-*.json`），在「设置 → 云同步」里可以查看、恢复、删除。选「以云端为准」覆盖本机时同理，本机那份也先留副本（内容只是默认的空列表 / 空对象就不留，免得新设备第一次同步平白多出一排）。**绝不静默丢数据**。

判定新旧用的是云端清单里的递增版本号，不是时间戳——设备时钟不准也不会判反。

### 什么时候同步

打开页面先拉一次（在渲染前完成，看到的就是最新数据）；**从别的应用切回这个标签页时也补一次**（同样受下面那个 30 秒窗口兜着，不算轮询）；改动后约 3 秒自动推；顶栏「同步」点开是面板，里面有「立即同步」。**不做后台轮询**，省请求也省钱（CloudBase 免费额度按月计，省下来的都是真额度）。

具体省在三处：

- **切页 / 刷新不白跑**：刚同步成功过、本机又没有待推的改动时，进页面这一轮**整轮跳过**（窗口 30 秒），连「读一次云端清单」都不做。在一堆页面之间来回切，不会每切一次就烧一次请求。
- **清单没变就不写**：一轮下来没有任何增删改，就不重写云端清单，顺带省掉「写清单前必读一次」那笔开销。
- **失败不算数**：跳过窗口以上一次**成功**同步为准。出过错之后切页会立刻重试，不会傻等窗口过期。

手动点「立即同步」、以及写完之后的自动推送**永远真跑**，不受上面两条影响——只要本机有改动，就一定推得上去。

### 读到的为什么不会是浏览器缓存里的旧副本

同一个 key 的下载链接是**稳定复用**的（`createSignedUrl` 在有效期内每次返回同一串），浏览器就按 URL 把第一次读到的响应存了下来。于是云端清单和各篇正文每轮同步都命中那份旧副本，而「旧清单 + 旧数据」哈希自洽，同步引擎一路报「两边本来就一致」，看着跟没同步一样。**典型症状是「电脑上改了，手机怎么点都不过来，清一次浏览器缓存立刻就好」**——云存储对象默认还不带 `Cache-Control`，浏览器只能按启发式缓存自行决定存多久，等于默认放行。

现在两头都堵住了：

- **写**：上传时显式带 `Cache-Control: no-store, no-cache, must-revalidate`，由云端明确表态「这份响应不许缓存」，浏览器和 CDN 都不再自作主张
- **读**：不走 SDK 的 `download`（它内部把请求头写死成空对象，插不进东西），而是自己取一次签名链接再 `fetch`，这样才能说上那句 `cache: "no-store"`；同时带上 SDK 自带的 `cacheNonce`（每轮换一个 URL，按 URL 缓存必然落空），服务端万一不认这个参数，就自动退回不带它的签名链接
- 取签名链接的**字段名有两套**：新版对象接口返回 `fullSignedURL`，老版返回 `signedUrl`。只认一个的话会恒取到空串，然后**静默退回带缓存的常规下载**——通道白接，现象和没修一样，所以两套都认
- 拿不到链接、跨域被拦、浏览器不支持时一律退回常规下载，不改变原有行为，同步不会因此不可用

这条通道通不通**能从面板上直接看**，见下一节。

### 面板里能看到什么

顶栏那个带圆点的「同步」就是入口，圆点颜色即状态（已同步 / 有改动待推送 / 同步中 / 出错 / 待解锁）。点开后面板分四块，底部还有一排按钮：

- **状态行**：当前状态 +「上次同步 X」（刚刚 / N 分钟前 / N 小时前）。本机密钥对不上云端那份密文时，这里会多出「用同步密码对上云端」一块（见下面「限制与风险」）；第一次同步的对话框在云端有数据时会把「以云端为准」摆成主按钮
- **一排按钮**：「立即同步」「以云端为准」「检测连接」在左边，「关闭同步」在最右（要二次确认，只清本机配置和基准，云端和本机数据都不动）。「**检测连接**」是**怀疑没同步上就点它**：往云端真写一个探针文件再读回来，并单独跑一遍上面那条防缓存读取通道，结论原样显示在面板上（「开启同步」时自动跑的就是同一套检测，但以前只在那一刻出现，配好的设备再想看就没入口了）
- **健康度**：四格——「上次同步成功」「冲突副本」「版本差（云端领先几项 · 本地待推几项）」「最近一次失败」。失败会按**网络 / 凭证 / 权限 / 冲突**归类，并附一句该去查什么。算「版本差」需要读一次云端清单，所以只在**打开面板时**发生，不打开就不花这个请求
- **会同步哪些数据**：逐类列出会同步的东西、各自多大、有几篇笔记待推送，末尾写明哪些**不会**上云——不用翻文档也能自查
- **冲突副本**：查看 / 恢复 / 删除

### 手机上哪些功能没有

强依赖 Windows 本机服务的能力，在手机上**直接不显示入口**：代码（git）、更新软件版本、产品目录查询、剪贴板。**局域网传文件不在此列**——它只用局域网接口、不做本机校验，所以在别的设备上照常能浏览/上传/下载，只是「访问地址 + 二维码」那一块仍只在本机显示。资料库页的「指定文件夹 / 在资源管理器打开」、快捷方式的「打开」、首页工具菜单也会收起。其余（待办、周报、笔记、记账、菜谱、项目、回收站、资料库增删查）在手机上都能用。

收藏页在手机上能打开，但**清单和本体都不上云**（`files.json` 指向 `files/` 里的二进制文件），所以手机上看到的是新的空列表。记谱的歌曲跟着同步走，手机上能接着看。

出行路况走的是本机服务的只读接口，所以**手机上经局域网地址打开时能正常取数和看图**（前提是这台电脑的局域网访问开着、`baidu.local.json` 里配了 AK）。不过出行记录 `commute.json` 不参与云同步，手机和电脑是各自攒各自的样本；「把线路交给服务端定时采集」是写操作、只认本机页面（和 `/open`、扫盘一样），所以后端那份采集用的是电脑上打开页面时同步过去的线路。纯 HTTPS 托管页（不走本机服务）上既取不到数据、也没有后端采集。

### 限制与风险

- **密钥不进前端**：CloudBase 用匿名登录换临时凭证，不像直连对象存储那样把 SecretKey 放在浏览器里。但环境 ID 是公开的，所以**所有数据都端到端加密**，别人就算匿名登录进来拿到的也只是一堆解不开的密文
- **匿名登录要你自己开**：没开的话面板会提示去控制台开启
- **必须 HTTPS**：非安全上下文下浏览器不提供 `crypto.subtle`，同步用不了，手机上也进不去数据页
- **不做离线**：手机上断网只有上次缓存，离线可用需要 Service Worker（现在没有）
- **跨设备不是实时**：同步靠「打开页面 / 改动 / 切回这个标签页」触发，没有长连接推送。手机改完，电脑要等下一次真同步才看得到；受上面那个 30 秒窗口影响，最坏情况是多等半分钟。想立刻对齐就点「立即同步」。手机上标签页常年开着不刷新，靠「切回页面时补一次」这条兜底；拉回来的内容是新鲜的不是浏览器缓存里的旧副本（见上面两节），所以**不用为了看到新数据去清缓存或者重开页面**
- **云 SDK 要带对象存储接口**：上传下载走 `app.storage.from(桶名)` 这套对象接口（老接口在新一代环境下会一律回 `INVALID_PARAM`）。仓库里带的 `js/vendor/cloudbase.full.js` 已经是可用的那份，别换成旧版
- **桶名固定 `workbench`**：适配器默认只认这个桶名（配置里的 `bucket` 字段可覆盖，但面板上没有输入框，实际就是默认值），控制台建桶时名字要对得上
- **清浏览器数据会清掉 IndexedDB**：手机端的权威副本在云端，重新打开会自动拉回来
- **同步密码改不了**：只能「关闭同步」再重新配一次，重配时选「以本机为准」把数据重新推一遍
- **本机密钥对不上云端**：某台设备重建过云端（比如点了「以本机为准」重建）之后，其它设备手上那把密钥就解不开云端密文了，表现是**反复点「立即同步」都报同一句错、新加的东西一直不出现**。这时面板会多出一块「用同步密码对上云端」：填当初那把同步密码，本机重新按云端信封里的盐派一次密钥（当场验证），再选一次以哪边为准，本机文件不会被清掉。不用再走「关闭同步 → 重新开启」（那样会连基准一起清掉）。第一次同步的对话框在云端有数据时会建议「以云端为准」：刚配的手机上本机通常只有默认的空数据，选「以本机为准」等于把云端那份覆盖掉
- 本机同步基准 `sync-state.json` 存在数据文件夹里，不参与同步；桶里 `workbench/` 前缀下全是密文

## 更新发布的页面

页面是纯静态的，用 CloudBase CLI 传上去就生效，没有构建步骤：

```powershell
# 改了 js/ 下的脚本（同步逻辑、各页逻辑都在这里）
tcb hosting deploy ./js js -e <环境ID> --verify

# 改了页面本身（html / css）
tcb hosting deploy ./index.html -e <环境ID>       # 单文件也能直接发
tcb hosting deploy ./css css -e <环境ID> --verify
```

`--verify` 是发完再对一遍远端与本地是否一致，图个安心。命令不会删远端的东西（要删得显式加 `--prune`）。

**改了同步代码，两个戳要一起改、两边都要发**：

1. `js/sync-ui.js` 顶部的 `BUILD`（形如 `2026-10-03 16:40`）：改成发布日期时间。手机 / 别人电脑上打开「设置 → 云同步」拉到底会显示「同步面板构建 …」，和电脑端显示的**一致才算真的换上了新代码**（显示旧的那串、或压根没有这行 = 页面没重开，浏览器还在用内存里的旧 JS）
2. `index.html` 里 `sync-crypto.js` / `sync-core.js` / `sync-cloudbase.js` / `sync-ui.js` 四个 `<script>` 后面的 `?v=YYYYMMDD-HHMM`：和 `BUILD` 一起改

第 2 条是这套工程自己的约定。静态托管对 HTML / JS 回的是 `no-store`（实测 `no-store, no-cache, must-revalidate, max-age=0`），所以不带戳也不会拿到旧文件；戳的实际用处是**让「页面请求的是哪一版」和「代码自己报的是哪一版」始终对得上**——「改了没生效」时看一眼这两个数字就知道卡在哪一层，顺带挡住中间缓存、Service Worker、以及换托管后缓存策略变了这些情况。

其它页面（todo / notes / …）引用同步脚本时不带 `?v=`，只有 `index.html` 带，所以改完同步代码**别只发 `js/` 就完事**。

## 重新编译本地服务

改动 `scripts/workbench-host.cs` 后：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build-host.ps1
```

脚本会：备份当前 exe → 用 `csc` 编译 → 停掉旧进程 → 替换 → 重启。**编译失败不会动正在用的 exe**；需要回滚时执行 `build-host.ps1 -Rollback`。

## 数据与隐私

- 待办、周报、笔记、记账、记谱、资料库全部写在你选择的数据文件夹里，是**可读的纯 JSON 文件**（收藏页存进来的文件本体也在同一个文件夹的 `files/`、`screenshot/` 里），随时可以自己备份、查看、手工修改
- 资料库用主密码加密（AES-GCM），密文落盘为 `vault.json`，每次保存前会留一份 `vault.backup.json`
- 「DeepSeek」的余额缓存存在数据文件夹的 `deepseek.json`（明文可读可改，不含任何按天记录）
- 「出行路况」的线路配置（起点终点，通常就是家庭住址）和历史样本都在数据文件夹的 `commute.json`，明文可读可改；后端定时采集用的线路和攒下的样本分别在仓库根目录的 `commute.local.json`、`commute-spool.json`（同样带起终点，不进版本库、不参与云同步）；**百度 AK 存在仓库根目录的 `baidu.local.json`，只被本机服务读，既不进版本库也不出现在页面里**（调百度的是本机服务，不是浏览器）
- **没开云同步时**，除 AI 润色（把周报文本发给你自己配置的模型接口）、口述记账（点「解析」才把那一句话发给模型，换回结构化字段）和首页余额查询（只带 API Key 问一次余额）外，**没有任何数据离开本机**
- **开了云同步后**，同步范围内的文件会**在本地加密后**传到你自己开通的腾讯云 CloudBase 环境，解密只在本机进行，云端只存密文；剪贴板历史、API Key、主密码、明文缓存、本机路径类配置都不在同步范围内（详见「云同步」一章）
- 本仓库已排除：`notes/`（数据）、`vault*.json`、`lan/`、`clipboard-history.json`、`catalog-index.json`（扫盘索引）、`js/openrouter.local.js`（密钥）、`baidu.local.json`（百度地图 AK）、`commute.local.json` 与 `commute-spool.json`（出行路况的后端采集：线路 + 样本）、`workbench.config.json`（本机路径）
